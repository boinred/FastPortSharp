# FastPortGameServerTemplate

Game-server starter template that sits on top of the FastPort network engine
(`FastPort.Common` + `FastPort.Networks`, the NuGet identifiers used by
`LibCommons` and `LibNetworks` in this monorepo).

It is intentionally minimal: a Generic Host wires up Serilog, a Protobuf-based
sample protocol, a session/handler/dispatcher trio, and a no-op telemetry hook.
Replace the sample handler with your own packet handlers to ship a game server.

## What is provided

| Concern | Implementation |
|---|---|
| Hosting | `Microsoft.Extensions.Hosting` (`Host.CreateApplicationBuilder`) |
| Logging | Serilog Console sink, configured from `appsettings.json` |
| Listener | `GameServer : LibNetworks.BaseMessageListener` |
| Per-session | `GameSession : LibNetworks.Sessions.BaseSessionClient` |
| Factory | `GameSessionFactory : IClientSessionFactory` |
| Dispatch | `PacketDispatcher` routes packet id → `IPacketHandler` |
| Sample | `EchoHandler` round-trips `EchoRequest` (1001) → `EchoResponse` (1002) |
| Protocol | `../Protos/Sample.proto`, generated by `Grpc.Tools` per consumer (shared folder, no separate csproj) |
| Telemetry | `IGameServerTelemetry` + `NullGameServerTelemetry` (replace via DI) |
| Config | `appsettings.json` → `GameServerOptions` (listen address/port, max sessions) |

## Project boundaries

- Depends only on `LibCommons` (engine: buffers, packet, IDs) and
  `LibNetworks` (engine: listener, session).
- Does **not** reference `FastPortServer`, `FastPortClient`, `Protocols/`,
  `LibTestTelemetry`, or any test project.
- The engine packages stay protocol-neutral and telemetry-free; game-server
  concerns live here.

## 5-minute echo bootstrap

```bash
# from the repo root
dotnet build FastPortSharp.sln -c Release
dotnet run --project template-projects/FastPortGameServerTemplate -c Release
```

Expected log on stdout:

```
[INF] GameServer starting. ListenAddress=0.0.0.0, ListenPort=7777, MaxSessions=1024
[INF] GameServer listening. Press Ctrl+C to stop.
[INF] Application started. Press Ctrl+C to shut down.
```

A TCP probe should succeed:

```bash
nc -zv 127.0.0.1 7777
# Connection to 127.0.0.1 port 7777 succeeded!
```

Connect a client and the session lifecycle hooks fire:

```
[INF] BaseSessionClient, OnAccepted. Id : 1, Remote End Point : ...
[INF] GameSession accepted. Id=1
[INF] BaseSessionClient, OnDisconnected. Id : 1, Remote End Point : ...
[INF] GameSession disconnected. Id=1
```

## Full echo round-trip with the bundled sample client

The repo ships a matching console client at `FastPortGameServerTemplate.SampleClient/`.
Start the server in one terminal, run the client in another:

```bash
# terminal 1
dotnet run --project template-projects/FastPortGameServerTemplate -c Release

# terminal 2
dotnet run --project template-projects/FastPortGameServerTemplate.SampleClient -c Release
```

Expected client output:

```
[INF] SampleClient connecting. Host=127.0.0.1, Port=7777
[INF] BaseConnector, OnSocketEventsConnectedCompleted, Connected to 127.0.0.1:7777
[INF] Connected. Sending EchoRequest. Message="Hello, FastPort!"
[INF] EchoResponse received. Message="Hello, FastPort!", ServerUnixMs=..., RTT=...ms
[INF] Echo round-trip succeeded. Echoed="Hello, FastPort!", RTT=...ms
[INF] ExitAfterOneEcho=true, stopping application.
```

Packet ids on the wire:

| Id | Direction | Message |
|----|-----------|---------|
| 1001 | C → S | `EchoRequest { string message }` |
| 1002 | S → C | `EchoResponse { string message; int64 server_unix_ms }` |

The sample client is intentionally minimal (~150 lines) and is a fine
starting point if you want to write a smoke probe or load runner against
your own game server.

## Customising

- **Add a new packet**: drop a `.proto` into `../Protos/`, add the packet id to
  this project's `Handlers/PacketIds.cs` (≥ 2000 for user-defined), rebuild,
  write an `IPacketHandler` in this project's `Handlers/`, and register it in
  `Program.cs`:

  ```csharp
  builder.Services.AddSingleton<IPacketHandler, MyHandler>();
  ```

- **Replace telemetry**: implement `IGameServerTelemetry` (e.g. on
  OpenTelemetry) and replace the registration in `Program.cs`.

- **Tune buffers**: edit `BufferCapacityBytes` in
  `Sessions/GameSessionFactory.cs` (default `8 KiB`, mirroring the validated
  10K-session benchmark configuration).

## Distribution

Use this repository as a **GitHub Template Repository**: click "Use this
template" on GitHub, or clone/fork and prune the projects you don't need.
Inside a single solution, reference the engine via `ProjectReference` to
`LibCommons` / `LibNetworks` (this is what the template itself does).

Uploading the engine to nuget.org is **out of scope** for this project. The
`PackageId` metadata in `LibCommons.csproj` / `LibNetworks.csproj` exists for
local identification only — `GeneratePackageOnBuild=false` and there is no
publish workflow.
